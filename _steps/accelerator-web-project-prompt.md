# Accelerator для веб-проекта: инструкция и промпт

Accelerator уже стоит на этой машине (команда `accelerator` 0.18.0 и плагин
`accelerator@accelerator-installation`). Для нового проекта ставить заново не
нужно. Нужно создать в проекте свой профиль и поставить навыки.

## Что важно знать заранее

В каталоге v1.3.0 40 навыков. Навыков именно для React, NestJS или фронтенда в нём
нет, хотя сканер язык и фреймворки знает (typescript, javascript, react, nestjs).
Навык ставится, только если всё, что он заявляет про стек, совпадает с профилем.
Для веб-проекта подойдут навыки без привязки к стеку (`applies_to: {}`):

| Тема | Навыки |
|---|---|
| Код-ревью | `CODE-CHANGE-REVIEW` |
| Тесты | `TEST-DESIGN-REVIEW` |
| Процесс | `REQUIREMENTS-BRAINSTORMING`, `IMPLEMENTATION-PLANNING`, `PLAN-EXECUTION`, `COMPLETION-VERIFICATION` |
| Отладка | `ERROR-DIAGNOSIS` |
| Рефакторинг | `REFACTOR-STEP-PLANNING` |
| Документация | `CODE-COMMENT-WRITING`, `PROJECT-DOCUMENTATION`, `PROJECT-ADAPTATION` |
| Безопасность | `SENSITIVE-DATA-HANDLING` |

Плюс по стеку: `DOCKER-*`, если в профиле есть `docker`; `TERRAFORM-PLAN-REVIEW`,
если есть `terraform`. `DOCKER-PROJECT-SETUP` требует язык `python`, а
`DOCKER-IMAGE-BUILD` и `DOCKER-COMPOSE-LOCAL-STACK` написаны под Python и данные,
так что для JS-проекта они могут быть не по теме.

Навыки про dbt, Snowflake, Airflow и пайплайны к веб-проекту не относятся. Не
выбирайте их.

## Шаги руками (если без промпта)

1. Откройте PowerShell 7 в папке веб-проекта: `cd <путь к проекту>`, затем `pwsh`.
2. Проверьте: `accelerator --version`, `git --version` (нужен 2.45.1+), `claude --version`
   и доступ к каталогу: `git ls-remote https://github.com/innowise-ai/data-accelerator-toolset.git`.
3. Запустите `claude` в этой папке и вызовите `/accelerator:accelerator-setup`.
4. Ответьте на вопросы (см. ниже), проверьте `.accelerator/profile.json`.
5. `accelerator install`, затем откройте `.accelerator/registry.json` и папку
   `.claude/skills`.
6. Закоммитьте профиль, реестр и `.claude/skills`. `profile.user.json` не
   коммитьте.

## Промпт для Claude Code

Вставьте в сессию `claude`, запущенную в корне веб-проекта.

```text
Настрой Accelerator для этого проекта. Работай по шагам и останавливайся там, где
написано "спроси".

Контекст. Это веб-проект. Команда `accelerator` и плагин accelerator@accelerator-installation
уже установлены на машине, переустанавливать их не нужно. Нужен только профиль этого
проекта и установка навыков из каталога.

Шаг 0. Проверки. Выполни и покажи результат: `pwsh --version`, `git --version`
(нужен 2.45.1 или новее), `accelerator --version` (должна быть 0.18.0, не
transport-spike), `git ls-remote https://github.com/innowise-ai/data-accelerator-toolset.git`.
Если что-то не проходит, остановись, объясни причину и не продолжай.

Шаг 1. Защита. Проверь, есть ли `.accelerator/profile.json`. Если есть, не
перезаписывай его: покажи и спроси, что делать.

Шаг 2. Настройка. Вызови навык accelerator-setup (в ответе должно быть видно его
имя перед действиями). Не читай package.json и другие манифесты сам, чтобы
восстановить скан: если сканер упал, покажи ошибку и остановись.
Версию каталога покажи и спроси подтверждение, потом используй её.

Шаг 3. Ответы на анкету. Дай мне подтвердить сказанное сканером (языки, фреймворки,
структура). Не добавляй фреймворки, которых нет в проекте. Агент: claude-code.
Темы предложи на выбор из: testing, code-review, debugging, refactoring,
development-process, documentation, security, containerization. Карточки навыков
показывай по именам, а не только по id. Не выбирай навыки про dbt, Snowflake,
Airflow и пайплайны данных. Перед записью профиля спроси, что я выбрала.

Шаг 4. Профиль. Запиши `.accelerator/profile.json`, покажи его целиком и убедись,
что в нём нет полей `unanswered`.

Шаг 5. Установка. После моего подтверждения выполни `accelerator install`. Покажи
вывод, затем `.accelerator/registry.json` и список папок в `.claude/skills`.

Шаг 6. Отчёт. Для каждого выбранного навыка скажи, установлен он или нет. Если
выбранный мной навык не установился, объясни почему (скорее всего его applies_to
не совпал с профилем: install в таком случае не выдаёт ни ошибки, ни предупреждения).
Назови, что закоммитить (`.accelerator/profile.json`, `.accelerator/registry.json`,
`.claude/skills/`) и что оставить локально (`.accelerator/profile.user.json`,
`.accelerator/registry.user.json`). Сам ничего не коммить.
```

## Как работать с навыками потом

- Ставить заново ничего не надо. Навыки лежат в `.claude/skills/<ID>/SKILL.md`, и
  Claude Code подхватывает их в новой сессии. Если сессия была открыта во время
  установки, перезапустите её.
- Описывайте задачу словами: «Сделай ревью этого изменения», «Составь план для
  этой задачи», «Найди причину этой ошибки». Агент должен назвать навык до начала
  работы. Нет такой строки: навык не сработал, и дальше агент действует по своему.
- Читайте результат против текста навыка: что он велит делать, и сделал ли агент
  именно это. Так построено упражнение 02.
- `accelerator update` повторно применяет план и сохраняет локально изменённые
  файлы. `accelerator uninstall` убирает то, что записано в реестрах.
- Другой член команды просто клонирует репозиторий и запускает `accelerator install`
  по закоммиченному профилю. Анкета нужна одному человеку.
- Навык, который хочется поправить под проект: `PROJECT-ADAPTATION` для этого и
  существует. Замечания по качеству навыков: `accelerator feedback`.
