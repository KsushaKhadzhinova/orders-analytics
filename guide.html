0 из 7 шагов

1. Программы: PowerShell 7, Git, Python 3.11, Claude Code

Где: обычный PowerShell · Время: 10–15 минут

Dbt 1.7 не работает на Python 3.12 и новее, поэтому нужен именно 3.11.

winget install --id Microsoft.PowerShell
winget install --id Git.Git
winget install --id Python.Python.3.11

Claude Code установите по официальной инструкции Anthropic. Затем откройте новое окно терминала и проверьте версии:

pwsh --version
git --version
py -3.11 --version
claude --version

2. Установить accelerator и навык accelerator-setup

Где: папка installation из курса · Время: 5 минут

Распакуйте папку installation и запустите скрипт из неё. Не используйте install.ps1 и install.sh: они ставят только команду, без навыка.

cd C:\путь\к\installation
pwsh -File install-accelerator.ps1 --agent claude
PowerShell не даёт запустить скрипт 
Set-ExecutionPolicy -Scope Process Bypass -Force

Откройте новое окно терминала и проверьте:

accelerator --version

Ожидаемо: первая строка — версия (например, 0.18.0), затем пути launcher, module, pwsh и git. Если Claude Code был открыт во время установки, перезапустите его.

3. Pester 5.6.1 (для Epic-03)

Где: PowerShell · Время: 2 минуты

Install-Module Pester -RequiredVersion 5.6.1 -Scope CurrentUser -Force -SkipPublisherCheck
Import-Module Pester -RequiredVersion 5.6.1
(Get-Module Pester).Version.ToString()

Последняя строка должна вывести 5.6.1. Другая мажорная версия Pester не подходит.

4. Рабочая копия проекта

Где: PowerShell · Время: 1 минута

Скопируйте папку fixture из папки exercises в отдельное место. Работайте в копии, а не в папке из курса.

Copy-Item -Recurse C:\путь\к\exercises\fixture C:\Users\<вы>\orders-analytics
cd C:\Users\<вы>\orders-analytics

5. Окружение Python и пакеты

Где: папка проекта в PowerShell · Время: 3–5 минут

Скрипт scripts\setup-env.ps1 из этого репозитория: находит Python 3.11, создаёт .venv, ставит все пакеты одной командой и запускает pip check. Сам скрипт положите в папку scripts проекта (скопируйте из репозитория).

powershell -ExecutionPolicy Bypass -File scripts\setup-env.ps1
Не ставьте dbt-core и dbt-duckdb отдельными командами: dbt-core заменится, и появится ошибка No module named 'dbt.adapters.factory'. Если так произошло, удалите .venv и запустите скрипт заново.

6. Проверка всего окружения

Где: папка проекта в PowerShell · Время: 1 минута

7. Если dbt или duckdb заблокированы Windows

Где: проверка и обращение к администратору · Время: зависит от IT

Симптомы:

  • dbt.exe выдаёт Permission denied;
  • import duckdb выдаёт An Application Control policy has blocked this file.

Политику безопасности не обходите: её меняет только администратор. Чтобы проверить, что dbt вообще работает, запустите через Python, чтобы проверить, что dbt вообще работает:

.venv\Scripts\python.exe -m dbt.cli.main --version

Если блокируется _duckdb, попросите администратора добавить исключение для папки .venv (или для файлов duckdb и _duckdb*.pyd). Приложите вывод check-env.ps1.
