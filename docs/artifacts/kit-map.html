Что такое Accelerator

Accelerator кладёт в проект небольшой набор навыков для AI-агента из общего каталога. Навык — это файл SKILL.md, по которому агент (Claude Code, Codex или Cursor) выполняет один вид задач.

1 · scanчитает проект, пишет profile.draft.json
2 · анкетанавык accelerator-setup спрашивает то, чего скан не знает, пишет profile.json
3 · installкопирует навыки в .claude/skills/, пишет registry.json

install ничего не спрашивает и не использует AI: один и тот же профиль всегда даёт один и тот же набор.

СловоЧто это
АртефактОдна запись в каталоге. Сейчас все артефакты — навыки.
Профиль.accelerator/profile.json: факты о проекте плюс ответы анкеты. Его коммитят.
Черновикprofile.draft.json: результат scan. Установить из него нельзя.
Реестрregistry.json: что поставил install и почему.
applies_toУсловия стека, которые навык заявляет. Если хоть одно не совпало с профилем, навык отфильтрован. {} значит «подходит всем».
strengthalways ставится сам в любой подходящий проект. on-demand ставится, только если его id выбрали. В каталоге v1.3.0 один always: DOCKER-DATA-LOSS-CONFIRMATION.
scopeproject идёт в профиль проекта, user — в личный profile.user.json, который не коммитят.
Фильтр и выборФильтр решает, какие карточки показать. Выбор — то, что человек отметил. Ставится только выбранное.

Упражнение 01. Профиль и установка

30 минут, шаг 8 добавляет около 15. Нужен рабочий accelerator и доступ к github.com.

Шаг 3. Сначала предскажите, потом сканируйте

Запишите заранее: какие языки найдёт скан, какие фреймворки и найдёт ли Snowflake. Затем:

accelerator scan -ToolsetRef refs/tags/v1.3.0

Ожидаемый результат: языки python и sql (первый из requirements.txt, второй из моделей), фреймворк dbt (два сигнала: dbt-core и dbt_project.yml), Snowflake не найден. В черновике это видно: test_runner: pytest, layout: single, uncertain: ["stack.languages"].

Шаг 4. Установка из черновика не работает

В provenance черновика три поля unanswered: agents, intents, selected_artifacts. accelerator install отвечает Profile not found: …/profile.json и указывает на навык настройки. Это правильный результат.

Шаг 5. Анкета

claude
/accelerator:accelerator-setup
  1. Языки и фреймворки: принять python, sql, dbt. Snowflake не добавлять.
  2. Темы: testing и data-quality.
  3. Карточек будет восемь, взять три: «Pick dbt schema tests for each column role» (DBT-MODEL-TESTING), «Define what belongs in each dbt layer» (DBT-LAYER-BOUNDARIES), «Test pipeline code with pytest, mocking I/O» (PYTEST-DATA-PIPELINES).
  4. Агент: claude-code. С пустым agents профиль нельзя установить.

Агент должен назвать навык accelerator-setup до начала работы. Если строки нет, навык не сработал.

Шаг 6. Установка и три вопроса

После accelerator install в реестре три навыка, у каждого "strength": "on-demand". Ответьте письменно:

ВопросМой вывод из правил отбора
(a) Почему AIRFLOW-DAG-STRUCTURE не было среди восьми карточек?У него applies_to: {"frameworks":["airflow"]}, а в профиле нет airflow. Одно несовпавшее условие отфильтровывает навык.
(b) Почему DATA-INCIDENT-TRACING с applies_to: {} показали?Пустое applies_to подходит любому стеку, а его темы debugging и data-quality пересекаются с выбранной вами data-quality.
(c) Что сделал бы always-навык? Есть ли такой в каталоге?always ставится в любой подходящий проект без выбора. По тестам упражнения 03 в каталоге ровно один: DOCKER-DATA-LOSS-CONFIRMATION. Ему нужен Docker в профиле, поэтому здесь он не встал.
В документе ответов нет. Это мой вывод из правил и из файла catalog-topics.json, сверьте его с сертификатором на ревью.

Шаг 8 (по желанию). Меняем одно поле и предсказываем разницу

Добавить snowflake в stack.frameworks, поставить intents в ["performance"], выбрать DBT-INCREMENTAL-STRATEGY и три SNOWFLAKE-*. Перед install записать, сколько навыков встанет и что будет с исходными тремя. Потом убрать только слово snowflake и предсказать реестр ещё раз.

Упражнение 02. Применить навык

90 минут. Агент пишет тесты, вы проверяете его работу по тексту навыка. Начинается с профиля и реестра, которые оставило упражнение 01.

Шаг 1. Окружение

py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt "dbt-duckdb==1.7.5"
pip check          # No broken requirements found
dbt debug          # All checks passed!

Манифест и адаптер ставятся одной командой. Вторая команда pip заменит dbt-core, напечатает ошибку и всё равно завершится успешно; сломается всё на следующем вызове dbt: No module named 'dbt.adapters.factory'. Лечение одно: удалить .venv и поставить заново. В requirements.txt dbt-duckdb не добавлять, иначе изменится профиль.

Файл profiles.yml лежит в корне проекта:

orders_analytics:
  target: dev
  outputs:
    dev:
      type: duckdb
      path: orders.duckdb

Шаг 2. Данные с изъянами

Скопировать seeds/ и ORDER-STATUSES.md, заменить source('shop','raw_orders') на ref('raw_orders') (и то же для клиентов), удалить блок sources: из schema.yml, затем dbt seed и dbt build. Всё это делает _steps\step3.ps1. Результат: 4 клиента, 7 заказов, PASS=9 WARN=0 ERROR=0.

Зелёная сборка не значит, что данные в порядке. В сидах два дефекта:

СтрокаЧто не такКакой тест поймает
Заказ O1005customer_id = C999, такого клиента нетrelationships
Заказ O1006статус refunded, которого нет в согласованныхaccepted_values

Согласованные статусы (март 2024): pending, shipped, completed, cancelled. Обычный путь pending → shipped → completed; cancelled конечный и следует только за pending.

Шаг 3. Прочитайте навык до агента

После запуска агента сравнивать его работу будет не с чем. Откройте .claude/skills/DBT-MODEL-TESTING/SKILL.md, затем проверьте: список YAML с тестами в models/, есть ли packages.yml (нет, значит тестов dbt_utils здесь не будет). Запишите правило выбора столбцов и два анти-паттерна.

Что в навыке (конспект)
Роль столбцаТесты
Первичный ключunique и not_null вместе: это выражение зерна модели
Внешний ключnot_null, relationships
Категориальныйaccepted_values; значения подтверждает владелец данных, а не сегодняшние строки
Обязательное бизнес-полеnot_null

Упавший тест чаще прав: сначала посмотрите строки (dbt show --inline), потом решайте. severity: warn не прячет настоящие падения.

Анти-паттерны: dbt_utils без проверки packages.yml; unique без not_null на ключе; ослабить тест, не выяснив причину; accepted_values из сегодняшних значений; настоящее падение в warn; тесты только на очевидных столбцах; модели без тестов.

Шаг 4. Агент пишет, вы проверяете

В чат с агентом отправьте ровно это, ничего не добавляя и не вставляя правила навыка:

Add tests to models/schema.yml

Затем откройте дифф и для каждого теста назовите правило навыка, которое его оправдывает. Итог должен содержать:

  • тесты на stg_customers: unique и not_null на customer_id;
  • relationships на stg_orders.customer_id к stg_customers, но не unique;
  • accepted_values на stg_orders.status; выясните, откуда взят список значений;
  • больше покрытия на fct_daily_orders, чем один order_date;
  • ни одного теста из dbt_utils или dbt_expectations.

«Выглядит правильно» ревью не считается. Назовите один столбец, который вы оставили без теста, и почему это верно. Проверка разбора YAML: dbt parse.

Сейчас в models\schema.yml только unique и not_null на stg_orders.order_id и fct_daily_orders.order_date. Копия до правок лежит в %TEMP%\schema.before.yml.

Шаг 5. Запуск и реакция на красное

dbt test
dbt show --inline "select * from {{ ref('stg_orders') }}"

Ожидаемо упадут тесты на O1005 и O1006. Для каждого падения до правки запишите, что неверно: данные или тест, и почему. Правьте там, где проблема. Тест меняете: причину пишите в YAML. Данные меняете: снова dbt seed. Затем dbt test должен быть зелёным.

Шаг 6. Три заметки

  1. Что агент сделал не так (или что вы проверили, если всё верно).
  2. Одно, что навык подсказал и вы бы пропустили сами.
  3. Одно, что вы сделали иначе, чем в навыке, и почему. «Ничего» не годится.

Другой проект: веб-разработка

Ставить Accelerator заново не нужно: команда и плагин уже на машине. Для нового проекта нужен свой профиль и установка навыков.

Чего ждать от каталога. В v1.3.0 40 выбираемых навыков, и среди них нет навыков именно под React или NestJS: сканер эти фреймворки знает, но навыки в основном про dbt, Snowflake, Airflow, Docker, Terraform и Python. Веб-проекту подойдут навыки без привязки к стеку: CODE-CHANGE-REVIEW, TEST-DESIGN-REVIEW, REQUIREMENTS-BRAINSTORMING, IMPLEMENTATION-PLANNING, PLAN-EXECUTION, COMPLETION-VERIFICATION, ERROR-DIAGNOSIS, REFACTOR-STEP-PLANNING, CODE-COMMENT-WRITING, PROJECT-DOCUMENTATION, PROJECT-ADAPTATION, SENSITIVE-DATA-HANDLING. Docker-навыки написаны под Python и данные.

Шаги руками

  1. PowerShell 7 в папке проекта. Проверить accelerator --version, git --version и доступ к каталогу.
  2. Запустить claude в корне и вызвать /accelerator:accelerator-setup.
  3. Подтвердить скан, выбрать агента claude-code, темы и карточки. Навыки про dbt и пайплайны не брать.
  4. Проверить .accelerator/profile.json, выполнить accelerator install, открыть registry.json и .claude/skills.
  5. Закоммитить профиль, реестр и .claude/skills. profile.user.json и registry.user.json не коммитить.

перезаписывай его: покажи и спроси, что делать.

Шаг 2. Настройка. Вызови навык accelerator-setup (в ответе должно быть видно его
имя перед действиями). Не читай package.json и другие манифесты сам, чтобы
восстановить скан: если сканер упал, покажи ошибку и остановись.
Версию каталога покажи и спроси подтверждение, потом используй её.

Шаг 3. Ответы на анкету. Дай мне подтвердить сказанное сканером (языки, фреймворки,
структура). Не добавляй фреймворки, которых нет в проекте. Агент: claude-code.
Темы предложи на выбор из: testing, code-review, debugging, refactoring,
development-process, documentation, security, containerization. Карточки навыков
показывай по именам, а не только по id. Не выбирай навыки про dbt, Snowflake,
Airflow и пайплайны данных. Перед записью профиля спроси, что я выбрала.

Шаг 4. Профиль. Запиши `.accelerator/profile.json`, покажи его целиком и убедись,
что в нём нет полей `unanswered`.

Шаг 5. Установка. После моего подтверждения выполни `accelerator install`. Покажи
вывод, затем `.accelerator/registry.json` и список папок в `.claude/skills`.

Шаг 6. Отчёт. Для каждого выбранного навыка скажи, установлен он или нет. Если
выбранный мной навык не установился, объясни почему (скорее всего его applies_to
не совпал с профилем: install в таком случае не выдаёт ни ошибки, ни предупреждения).
Назови, что закоммитить (`.accelerator/profile.json`, `.accelerator/registry.json`,
`.claude/skills/`) и что оставить локально (`.accelerator/profile.user.json`,
`.accelerator/registry.user.json`). Сам ничего не коммить.

Как работать потом

  • Навыки лежат в .claude/skills/<ID>/SKILL.md. Новая сессия их подхватывает; открытую во время установки перезапустите.
  • Описывайте задачу словами: «Сделай ревью этого изменения», «Составь план», «Найди причину этой ошибки». Агент должен назвать навык до работы.
  • Сверяйте результат с текстом навыка, как в упражнении 02.
  • accelerator update повторно применяет план и сохраняет правки файлов; accelerator uninstall убирает то, что записано в реестрах.
  • Коллега клонирует репозиторий и запускает accelerator install по закоммиченному профилю. Анкета нужна одному человеку.
