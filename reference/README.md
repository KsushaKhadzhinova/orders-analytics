# Эталонное решение упражнения 02

Это готовое решение для сравнения. Откройте его **после** того, как сделали своё.

## Что здесь

| Что | Где |
|---|---|
| Тесты (14 штук) | `models\schema.yml` |
| Данные после исправления | `seeds\raw_orders.csv` (без O1005 и O1006) |
| Вынесенные строки и причины | `quarantine\raw_orders_rejected.csv`, `QUARANTINE.md` |
| Настоящие выводы dbt по порядку | `_run\*.txt` |

## Журнал запусков в `_run`

| Файл | Что показывает |
|---|---|
| `01-seed.txt`, `02-run.txt` | исходная загрузка и сборка (до тестов) |
| `03-parse.txt` | `dbt parse` без ошибок |
| `04-test-red.txt` | `dbt test`: PASS=12, ERROR=2 из 14 |
| `05-...`, `06-...`, `07-...` | строки за падениями и все заказы |
| `10-fct-before.txt` | итог по дням до правки |
| `11-seed-fixed.txt`, `12-build-no-full-refresh.txt` | загрузка исправленных данных и обычная сборка |
| `13-fct-stale.txt` | итог после обычной сборки: СТАЛЫЙ (день 2024-02-03 остался) |
| `14-build-full-refresh.txt`, `15-fct-fresh.txt` | сборка с `--full-refresh` и верный итог |
| `16-test-green.txt` | финальный `dbt test`: PASS=14 |

## Оговорки

- Тесты писала я сама по навыку `DBT-MODEL-TESTING`, а не агент по фразе из упражнения.
- Решение по двум плохим заказам (карантин) — мой выбор. Другой допустимый путь для `refunded`: подтвердить статус у владельца данных, дописать его в `ORDER-STATUSES.md` и в тест, вернуть строку.
